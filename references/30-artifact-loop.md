# 通用交付物迭代

仅用于 `iterate_mode: artifact`。适用于文档、代码、提示词、表格、演示稿、网页、设计文件等可编辑产物。先读取现有产物及相关项目说明；如有该格式的专用 skill 或工具，遵循其制作与验证要求。

## Brief

记录 `artifact_path_or_target`、`artifact_type`、`goal`、`done_when`、不可变项、可观察的 `expected_checklist`、`max_rounds`（默认 5）。无现有文件时记录拟创建的交付物。用户未给细化标准时，从目标和用途推导合理的可验证条件，并标明推断。

## 每轮

1. **Plan**：选择未达标项与最小修改范围，记住已通过项。
2. **Produce**：修改目标产物，保留可实际恢复的上一版或差异。按相应格式的正常工作流制作，不把本 skill 当成格式编辑器。
3. **Verify**：使用真实产物验证。按需选择：文档/演示稿渲染并检查页面；代码运行针对性测试或实际场景；表格核对公式、数值和显示；网页检查运行与关键交互；提示词用代表性输入试跑并查看输出；设计文件检查节点和视觉结果。不可用或成本明显时，说明未验证范围。
4. **Evaluate**：逐项写 `expected / actual / status` 和证据位置。硬性条件未满足即 fail；可选评分只辅助排序，不覆盖清单结果。
5. **Diagnose**：定位失败原因、修复范围和回归风险。下一轮先处理硬性失败，再处理质量改进。不要反复改措辞而不检查效果。

## 结束

清单硬性项满足且必要验证通过时 `pass`。否则在轮次上限交付 `best_so_far`，说明未满足项、验证限制与可执行的下一步。最佳版本优先比较硬性条件、已满足项目及实际验证结果；不能仅凭“最新”选择。发布、部署、发送或写入外部系统只在已有授权范围内执行。
