# 指标优化迭代

仅用于 `iterate_mode: optimization`。对象是已有系统或流程的可测表现，例如延迟、吞吐、错误率、成本、资源消耗、检索准确率或可用性。新功能正确性归 `feature`；单个文稿或文件质量归 `artifact`。

## 目标与基线

先定义主指标的计算方法、单位、目标值、采样范围和测量环境。记录不可退化的护栏指标，例如正确性、稳定性、可访问性或成本。读取现有约束和历史数据；基线未知则先测。若指标受噪声影响，使用相同工作负载和足够重复次数，记录分布或波动范围。不得用不同环境下的数字直接比较。

例：`p95 延迟 ≤ 300 ms`，在固定请求集和相同环境中测量；护栏为错误率不升高、结果正确性不下降。

## 每轮

1. **Diagnose**：根据基线、剖析结果或失败样本提出可检验的原因。
2. **Change**：一次聚焦一个主要变量，记录变更和预期影响；对外部流程的改动仍受原任务授权约束。
3. **Measure**：在与基线一致的条件下重测主指标和护栏。保存原始命令、样本、配置与结果；无法复现时标 `unverified`。
4. **Compare**：报告改动前后数值、波动和可能的混杂因素。主指标改善但护栏退化时不判通过。结果落在噪声内时写“未证实改善”。
5. **Decide**：达到目标且护栏通过则结束；否则保留最佳有效版本，撤回已证实退化的改动，下一轮依据证据调整假设。

## 停止

达到目标、轮次上限、测量环境不可靠或继续操作超出授权范围时停止。交付最佳版本、测量方法、前后对照、尚未解决的瓶颈和未验证项。不要宣称统计显著性，除非实际做了适当分析。
