# 意图识别与模式路由

判断用户最终要收取的主交付物，而不是参考材料或使用的工具。

| 主交付物 | iterate_mode | 例子 |
|---|---|---|
| 图片、插画、照片 | `image` | 用某画风 skill 把输入图修到合格 |
| skill 的规则、触发描述或配套资源 | `skill` | 改 skill，让以后同类图更稳定 |
| 可运行的软件功能或交互 | `feature` | 开发登录、搜索、导出等功能，迭代到验收场景通过 |
| 已有系统或流程的可测表现 | `optimization` | 降低延迟、减少错误率、提高检索准确率、优化资源消耗 |
| 其他可编辑产物 | `artifact` | 文档、代码、提示词、表格、演示稿、网页、设计文件多轮改进 |

开发新行为或修正功能正确性选 `feature`；改进已有行为的量化表现、需要基线对照时选 `optimization`。

功能可能涉及代码、配置、接口、数据库及界面；主交付是可用功能时选 `feature`，即使要改多个文件。主交付是单个代码文件、库或模板本身时选 `artifact`。

“先改提示词再出一张合格图”属于 `image`；“把提示词模板本身打磨好”属于 `artifact`。代码生成图片时，若主交付是图片则选 `image`，若主交付是生成器代码则选 `artifact`。一个请求有多个主交付时，按用户指定的顺序处理；无顺序时根据依赖关系安排，并分别验收。只有对象仍不清楚且会改变工作方向时，才问用户。

记录 `iterate_mode`、对象、判定依据。后续沿用，除非用户明确改变主交付物。
