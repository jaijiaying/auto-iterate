# 意图识别与模式路由

在写 Brief 或 Produce 之前完成。只判定 `iterate_mode`，不在此步改图或改 skill。

## 判定问题

用户真正要迭代的**对象**是什么？

- 对象 = 画面结果 → `image`
- 对象 = skill 规则文本（`SKILL.md` / `references/` / 脚本说明等）→ `skill`

## 信号表

### 偏向 `image`

- 提供了待改图，并谈目标内容、构图、最终画面样式
- 用语：改图、修图、重绘、局部修、出图、画面达标、迭代到过关图
- 「按某某画风 skill 生成/转绘，不好就继续改图」
- 交付期望是图片文件

### 偏向 `skill`

- 指向 skill 目录、`SKILL.md`、references、验收规则、触发描述
- 用语：写 skill、改 skill、迭代 skill、调试规则、补参考文档、把 skill 打磨到可用
- 「生成结果不对，是 skill 规则有洞，要改 skill」
- 交付期望是 skill 文件变更（试跑图仅作验证）

### 冲突消歧

| 用户说法 | 判定 |
|----------|------|
| 用 A skill 把这张图改对 | `image`（A 为工具） |
| 改 A skill，让以后这类图都能对 | `skill` |
| 图不对，先改提示词再出一张 | `image` |
| 图不对，因为规则没写清专黑线，去改 references | `skill` |
| 又要改 skill 又要出最终海报 | 问用户本次主交付；默认先 `skill` 再另开 `image`，或按其指定 |

## 置信度

- `high`：对象明确，或用户点名模式
- `medium`：信号一致但未点名对象
- `low`：两种信号都有，或只说「迭代一下」而无对象 → **必须确认**

## 确认话术（仅 low / 冲突时）

只问一句，给两个选项，例如：

> 这次是要 **迭代图片**（改画面到过关），还是 **迭代 skill**（改规则文件到过关）？

## 锁定

- 将结果写入 `runs/<session_id>/intent.md`
- 本会话后续轮次沿用该 `iterate_mode`，除非用户明确要求切换
