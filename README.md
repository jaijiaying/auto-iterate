# auto-iterate

自动迭代编排 skill（初稿）：先根据用户意图识别模式，再进入 **图片迭代** 或 **skill 迭代**，按「产出 → 评测 → 诊断 → 再改」循环，直到达标或达到轮次上限。

> 本仓库是 skill 本体；详细执行规则在 `SKILL.md` 与 `references/`。Agent 调用时以 `SKILL.md` 为准。

## 能做什么

| 模式 | 迭代对象 | 适用场景 |
|------|----------|----------|
| `image` | 图片 | 输入图 + 目标 + 最终样式，多轮改图直到画面过关 |
| `skill` | skill 文件 | 写/改 `SKILL.md`、references，调试规则直到 skill 达标 |

每次会话只跑一种模式。易混例子：

- 「用某某画风 skill 把这张图改过关」→ **图片迭代**
- 「把某某 skill 改到以后这类图都能对」→ **skill 迭代**

## 怎么用

在 Cursor 里显式调用本 skill（`disable-model-invocation: true`，不会仅凭语境自动加载），并提供：

**图片模式最少信息**

- 输入图
- 目标（要完成什么）
- 最终结果样式

**Skill 模式最少信息**

- 目标 skill 路径
- skill 应具备的能力
- 怎样算达标（`done_when`）

可选：锁定项、自定义验收、最大轮次（默认 5）、下游画风 skill、试跑用例等。

## 流程概览

```
意图识别 → Brief（任务说明书）→ 多轮循环 → 终稿 / 当前最佳
```

每轮：`Plan → Produce → Evaluate → Decide`  
不达标则诊断差距，按最小充分修改进入下一轮。

**评测方式**：对照 Brief 里的目标与验收条件做检查清单式审阅（看实际图 / 读改后的 skill），不是和「金标图」做像素对比。

## Brief 是什么

进入循环前整理出的任务说明书，例如目标、样式、锁定项、达标条件。后续评测都对照这份 Brief。

## 边界

- 不代替具体画风 skill；图片模式下画风细节以绑定的下游 skill 为准
- skill 模式下试跑出图只作评测证据，主交付仍是 skill 文件变更
- 一次任务一个主模式；两种都要时拆成两次意图清晰的任务
